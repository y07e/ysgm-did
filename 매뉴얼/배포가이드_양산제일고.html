Part 1. 배포 전 준비

1.1 이 가이드를 사용하기 전

이 가이드는 양산여자중학교에서 운영 중인 전자칠판 DID 시스템을 양산제일고등학교에 설치하는 절차를 단계별로 안내합니다. 다른 학교에 배포할 경우 "양산제일고" 부분만 해당 학교 이름으로 바꿔 읽으면 됩니다.

🛈 시스템 구조 한눈에 이 시스템은 학교별로 독립된 Firebase 프로젝트 1개를 사용합니다. 데이터는 학교마다 완전히 분리되며, 양산여중의 데이터와 양산제일고의 데이터는 서로 보이지 않습니다. 인터넷 주소(URL)도 학교마다 별도로 부여됩니다.

1.2 필요한 것

항목설명
Google 계정Firebase 콘솔에 로그인할 학교 대표 Gmail 계정 1개
(가능하면 학교 공용 계정 — 담당자 교체 시 유리)
맥/PC배포 작업용 — 인터넷이 되는 컴퓨터면 충분
인터넷 브라우저Google Chrome 권장
학교 로고 이미지PNG 또는 JPG (정사각형, 512×512 이상 권장)
NEIS 학교 코드급식 정보 자동 표시용 — 1.3절에서 조회 방법 안내
나이스 시간표 엑셀각 학년별 1개 파일 (3개 학년 → 3개 파일)
학교 행정원/관리자 Gmail관리자 권한을 줄 사람들의 구글 계정
각 학급 전자칠판(IFP)인터넷이 연결되어 있어야 함
💡 비용 Firebase는 Spark 요금제(무료)로 충분합니다. 한 학교(예: 30개 학급, 1일 수천 회 조회) 정도 규모에서는 무료 한도 안에서 운영 가능하며, 신용카드 등록은 필요 없습니다.

1.3 학교 정보 수집 체크리스트

배포 전에 아래 정보를 모두 모아두세요. 이 표를 채우면 작업이 훨씬 빠릅니다.

📋 양산제일고 정보 수집 양식

  • 학교 정식 명칭: 양산제일고등학교
  • 학년별 반 수 — 예: 1학년 ( )반, 2학년 ( )반, 3학년 ( )반
  • NEIS 학교 코드 (7자리) — 예: 9290083
  • NEIS 교육청 코드 (3자리) — 경상남도교육청은 S10
  • 학교 로고 이미지 파일
  • 학교 대표 Gmail 계정 (Firebase 관리용)
  • 관리자 권한 줄 행정원/교무부장/교감 Gmail 목록 (3~5명)
  • 기초 수업 시간 (1교시 시작/끝, 점심 시작/끝 등)
  • 나이스 시간표 엑셀 파일 (학년별 1개씩)

NEIS 학교 코드 찾는 법

  1. https://open.neis.go.kr 접속
  2. 상단 메뉴 "NEIS 정보" → "학교/기관 코드 조회"
  3. 학교명 "양산제일고등학교" 검색
  4. 조회 결과의 "표준학교코드" 7자리 메모 (예시: 9290083)
  5. "시도교육청코드"도 함께 메모 (경남은 S10)
⚠ 학교코드 확인 필수 학교코드가 틀리면 급식 정보가 표시되지 않습니다 (다른 학교 급식이 나오는 사고도 가능). NEIS 사이트에서 직접 확인한 값을 사용하세요.

Part 2. Firebase 프로젝트 만들기

2.1 Firebase 콘솔 접속

1 학교 대표 Google 계정으로 Chrome에 로그인
2 https://console.firebase.google.com 접속
3 우측 상단 계정이 학교 대표 계정인지 확인

2.2 새 프로젝트 만들기 (yspil-did)

1 "프로젝트 추가" 또는 "Create a project" 클릭
2 프로젝트 이름 입력: yspil-did

💡 이 이름이 곧 인터넷 주소가 됩니다 → yspil-did.web.app
추천 명명 규칙: 학교 영문 약자 + "-did" (예: 양산제일고 → yspil)

3 프로젝트 ID가 자동 생성됨 — 그대로 사용 가능 (또는 직접 지정)
4 Google Analytics 안내 화면: "사용 안 함" 선택 권장 (불필요)
5 "프로젝트 만들기" → 30초~1분 대기

2.3 웹 앱 등록 + 키 발급

1 프로젝트 메인 화면에서 </> (웹) 아이콘 클릭
2 앱 닉네임 입력: yspil-did-web
3 "Firebase Hosting 설정" 체크박스 체크
4 "앱 등록" 클릭
5 중요! 표시되는 firebaseConfig 객체를 복사해서 메모장에 붙여넣기

아래와 같은 형태입니다 — 3장에서 사용합니다.

const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "yspil-did.firebaseapp.com",
  projectId: "yspil-did",
  storageBucket: "yspil-did.firebasestorage.app",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef..."
};
6 이후 단계(Firebase CLI 설치 등)는 4장에서 다루므로 지금은 "콘솔로 이동" 클릭

2.4 Authentication (Google 로그인) 활성화

1 좌측 메뉴 Build → Authentication 클릭
2 "시작하기" 클릭
3 "Sign-in method" 탭 → "Google" 선택
4 "사용 설정" 토글 ON
5 프로젝트 공개용 이름: 양산제일고 DID
지원 이메일: 학교 대표 Gmail 선택
6 "저장"

2.5 Firestore Database 활성화

1 좌측 메뉴 Build → Firestore Database 클릭
2 "데이터베이스 만들기" 클릭
3 위치 선택: asia-northeast3 (Seoul) 강력 권장
⚠ 위치는 나중에 변경 불가 한국 학교라면 반드시 서울 리전을 선택하세요. 잘못 고르면 DB를 새로 만들어야 합니다.
4 보안 규칙: "테스트 모드로 시작" 선택
(나중에 5장에서 실제 보안 규칙으로 덮어씁니다)
5 "사용 설정" → 1~2분 대기

2.6 Hosting 활성화

2.3절에서 이미 Hosting 설정이 포함되었으므로 추가 작업 없음. 좌측 메뉴 Build → Hosting으로 들어가서 "시작하기" 화면이 보이면 정상입니다. 실제 배포는 Part 4에서 진행합니다.

Part 3. 코드 복사 및 학교별 설정

3.1 코드 받기

두 가지 방법 중 편한 것을 선택하세요.

방법 A. GitHub에서 다운로드 (권장)

  1. 브라우저로 https://github.com/y07e/ysgm-did 접속
  2. 녹색 "Code" 버튼 → "Download ZIP" 클릭
  3. 다운로드된 ysgm-did-main.zip 압축 해제
  4. 폴더 이름을 yspil-did로 변경

방법 B. 양산여중 담당자에게 폴더 받기

  1. USB 또는 클라우드로 전자칠판DID 폴더 전체 받기
  2. 받은 폴더 이름을 yspil-did로 변경
  3. node_modules/, .firebase/ 폴더가 있으면 삭제 (재생성됨)

3.2 config.js 수정 (가장 중요)

배포 작업에서 실제로 학교별로 바꿔야 하는 파일은 단 1개입니다 — config.js. 이 파일만 정확히 수정하면 시스템 전체가 양산제일고용으로 동작합니다.

텍스트 에디터(메모장/VS Code 등)로 config.js를 열고 아래와 같이 수정:

const SCHOOL_CONFIG = {

  // 학교 기본 정보
  schoolName: '양산제일고등학교',           ← 변경

  // 학교 로고 (3.3절에서 교체)
  schoolLogo: '/logo.png',                ← 그대로

  // 학급 배지 옆 부제목
  boardTitle: '오늘의 정보',                ← 그대로 (또는 학교 표어)

  // Firebase 설정 — 2.3절에서 복사해둔 값으로 전체 교체
  firebase: {
    apiKey:            "AIzaSy...",                          ← 교체
    authDomain:        "yspil-did.firebaseapp.com",          ← 교체
    projectId:         "yspil-did",                          ← 교체
    storageBucket:     "yspil-did.firebasestorage.app",      ← 교체
    messagingSenderId: "123456789012",                       ← 교체
    appId:             "1:123456789012:web:abcdef..."        ← 교체
  },

  // 나이스 급식 API
  neis: {
    schoolCode: '9290083',   ← 양산제일고 실제 코드로 교체
    officeCode: 'S10'        ← 경남은 S10 그대로
  },

  // 학년별 반 수 — 양산제일고 실제 반 수로 교체
  gradeClasses: {
    '1': 10,                 ← 예시 (실제 학급 수 입력)
    '2': 10,
    '3': 10
  },

  // 기본 수업 시간표 — 양산제일고 실제 시간표로 교체
  defaultPeriods: [
    { period: 1, start: '08:40', end: '09:30' },   ← 50분 수업 (고교)
    { period: 2, start: '09:40', end: '10:30' },
    { period: 3, start: '10:40', end: '11:30' },
    { period: 4, start: '11:40', end: '12:30' },
    { period: 5, start: '13:30', end: '14:20' },
    { period: 6, start: '14:30', end: '15:20' },
    { period: 7, start: '15:30', end: '16:20' }
  ],

  // 기본 점심 시간
  defaultLunch: { start: '12:30', end: '13:30' },   ← 학교 실제 시간

  // 초기 관리자 이메일 (Firebase 관리자가 될 사람들)
  adminEmails: [
    'yspil.admin@gmail.com',          ← 최소 1명 (본인 Gmail)
    'principal@yspil.hs.kr',          ← 교감 등
  ],

  // 예시 교실 (테스트용)
  example: { grade: '1', class: '1' }
};
⚠ 흔한 실수
  • 따옴표 빠짐 — 문자열 양쪽에 작은따옴표 '...' 또는 큰따옴표 "..." 필수
  • 쉼표 , 빠짐 또는 잘못 추가 — 항목 사이엔 쉼표, 마지막 항목 뒤엔 쉼표 빼도 됨
  • 중괄호 { } 짝 안 맞음
  • 저장 시 인코딩이 ANSI가 되어 한글 깨짐 → UTF-8로 저장

3.3 로고 이미지 교체

  1. 양산제일고 로고 이미지를 준비 (정사각형, 512×512 이상 권장, PNG/JPG)
  2. 파일 이름을 logo.png로 변경
  3. 프로젝트 폴더의 기존 logo.png를 덮어쓰기
💡 로고가 없으면? logo.png를 그냥 두면 양산여중 로고가 그대로 표시됩니다. 없는 경우 config.js의 schoolLogo를 빈 문자열 ''로 두면 학교명 첫 글자로 자동 배지가 만들어집니다.

3.4 manifest.json 수정

PWA(앱) 이름을 학교 이름으로 변경:

{
  "name": "양산제일고 DID",                    ← 변경
  "short_name": "양산제일고",                   ← 변경
  "description": "양산제일고등학교 전자칠판 종합 알림판",  ← 변경
  ...
}

3.5 매뉴얼 학교명 변경

매뉴얼/ 폴더의 텍스트 파일들에서 "양산여중", "양산여자중학교"를 모두 "양산제일고", "양산제일고등학교"로 일괄 변경. 메모장의 "바꾸기" 기능으로 빠르게 처리 가능.

대상 파일:

  • 매뉴얼_관리자용.txt
  • 매뉴얼_담임용.txt
  • 매뉴얼_전자칠판_설치.txt
  • 전자칠판_셋업_바로가기.html (URL도 yspil-did.web.app으로 변경)

Part 4. Firebase CLI 설치 및 배포

4.1 Node.js · Firebase CLI 설치

Step 1. Node.js 설치

  1. https://nodejs.org 접속
  2. LTS 버전(왼쪽, 권장) 다운로드 → 설치 (모든 옵션 기본값 OK)
  3. 설치 확인: 명령 프롬프트(Windows) 또는 터미널(Mac)에서 
    node --version
npm --version
    버전 번호가 나오면 성공.

Step 2. Firebase CLI 설치

npm install -g firebase-tools

설치 확인:

firebase --version
🛈 권한 오류 시 Mac: sudo npm install -g firebase-tools
Windows: "관리자 권한으로 명령 프롬프트 실행" 후 재시도

4.2 Firebase 로그인

firebase login

브라우저가 자동으로 열리고 Google 로그인 화면이 나타남. → 학교 대표 Gmail로 로그인 → "Firebase CLI 권한 허용".

"Success! Logged in as ..." 메시지가 보이면 완료.

4.3 .firebaserc 설정

프로젝트 폴더(yspil-did/) 안에 .firebaserc 파일을 만들고 아래 내용을 입력:

{
  "projects": {
    "default": "yspil-did"
  }
}
💡 한 번에 만들기 (터미널) 
cd yspil-did
echo '{"projects":{"default":"yspil-did"}}' > .firebaserc

4.4 첫 배포

프로젝트 폴더로 이동한 후:

cd yspil-did
firebase deploy --only hosting

1~2분 후 아래와 같은 메시지가 나오면 성공:

✔ Deploy complete!

Hosting URL: https://yspil-did.web.app
✓ 브라우저에서 https://yspil-did.web.app 접속 → "양산제일고등학교" 화면이 보이면 성공!

4.5 보안 규칙 배포

Firestore 보안 규칙도 함께 배포:

firebase deploy --only firestore:rules

또는 한 번에 전체 배포:

firebase deploy
⚠ 보안 규칙 배포는 필수 2.5절에서 "테스트 모드"로 만든 Firestore는 누구나 데이터를 읽고 쓸 수 있는 상태입니다 — 30일 후 자동 차단되지만 그 전에 반드시 firestore.rules를 배포하여 보안을 적용하세요.

Part 5. 초기 운영 설정

5.1 최초 관리자 진입

  1. https://yspil-did.web.app/admin/ 접속
  2. "관리자 (Google)" 탭 선택
  3. config.js의 adminEmails에 등록한 Gmail로 Google 로그인
  4. 관리자 페이지가 정상적으로 열리면 성공
⚠ "등록되지 않은 계정"이 나오면?
  1. config.js의 adminEmails에 본인 Gmail이 들어있는지 확인
  2. 오타가 없는지 확인 (대소문자도 정확히)
  3. 수정 후 firebase deploy --only hosting으로 재배포
  4. 브라우저 새로고침 (캐시 강제 비우기: Ctrl+Shift+R)

5.2 관리자 추가 등록

최초 관리자가 다른 관리자를 추가:

  1. 관리자 페이지 → ⚙️ 설정 → 👥 교사 관리
  2. "관리자 추가" 버튼
  3. 이름, Gmail, 권한(관리자) 입력 → 저장
  4. 그 사람이 본인 Gmail로 로그인하면 즉시 관리자 권한 적용

5.3 담임 교사 등록

  1. 관리자 페이지 → ⚙️ 설정 → 👥 교사 관리
  2. "담임 추가" 버튼
  3. 이름, 이메일, 학년, 반, PIN(4자리, 예: 2026) 입력 → 저장
  4. 전체 담임을 한 번에 등록 권장 (학기 초 1회)

5.4 기초 시간표 입력 (NEIS 엑셀 일괄 업로드)

  1. 관리자 페이지 → 📅 일정 관리 → 기초 시간표 편집
  2. 📤 나이스 시간표 엑셀 업로드 버튼
  3. 학년별 엑셀 파일 선택 (1학년 → 2학년 → 3학년 순)
  4. 미리보기 확인 → "전체 학급에 적용"
💡 소요 시간 3개 학년 × 1개 파일씩 = 약 5분이면 전교 시간표 입력 완료.

5.5 급식 운영 기간 설정

  1. 관리자 페이지 → 🍱 급식 시간
  2. "새 운영 기간 추가" — 시작/종료일, 학급별 급식 시작 시각, 회전 주기 입력
  3. 저장 → 다음 달은 "📋 다음 달 복제" 버튼으로 빠르게 추가

5.6 학사일정 · D-Day 입력

  • 📆 학사일정: 한 주에 2건 권장. 금주(월~일) 일정만 자동 표시.
  • 🎯 D-Day: 시험·체육대회 등 동시 활성 2개 권장.

Part 6. 전자칠판(IFP) 설치

6.1 학급별 URL 확인

관리자 페이지 → ⚙️ 설정 → 🔗 교실 URL에서 전체 학급의 직접 링크 목록을 확인할 수 있습니다.

URL 형식:

https://yspil-did.web.app/display/?grade=1&class=1&desktop=1
https://yspil-did.web.app/display/?grade=1&class=2&desktop=1
...

desktop=1은 키오스크(전체화면 데스크톱) 모드를 강제하는 옵션입니다.

6.2 크롬에서 학급 페이지 열기

  1. 전자칠판(IFP)에 USB로 마우스/키보드 연결 (작업할 때만)
  2. Chrome 브라우저 실행
  3. 해당 학급 URL 입력 (또는 QR 코드 스캔)
  4. 학급 화면이 정상 표시되는지 확인

6.3 홈 화면에 추가 (PWA)

  1. Chrome 우측 상단 점 3개(⋮) 메뉴
  2. "홈 화면에 추가" 또는 "앱 설치" 선택
  3. 이름 확인 → "추가"
  4. 홈 화면에 앱 아이콘 생성됨 → 다음부터는 아이콘 한 번 누르면 전체화면 실행
🛈 "홈 화면에 추가" 메뉴가 안 보일 때 PWA 설치 메뉴는 다음 조건이 모두 충족되어야 보입니다:
  • HTTPS 접속 (yspil-did.web.app는 자동 HTTPS — 문제없음)
  • manifest.json이 정상 로드됨
  • Service Worker가 등록됨 (이미 코드에 포함됨)
  • Chrome 버전 76 이상
조건이 갖춰져도 메뉴가 보이지 않으면 페이지를 새로고침 후 다시 시도하세요.

6.4 키오스크 모드 자동 실행 (선택)

IFP를 24시간 자동 운영하려면 부팅 시 Chrome 키오스크 자동 실행을 권장:

  1. Android IFP의 경우: Fully Kiosk Browser 무료 설치
  2. Fully Kiosk에서 시작 URL을 학급 URL로 설정
  3. "부팅 시 자동 실행" 옵션 ON
  4. 화면 잠금 비활성화

  1. 최신 코드 다운로드 (GitHub에서 다시 받기 또는 양산여중 담당자에게 받기)
  2. 주의: config.js와 logo.png는 양산제일고 것을 그대로 유지 (덮어쓰지 말 것)
  3. firebase deploy 실행
💡 업데이트 시 안전한 방법
  1. 기존 config.js, logo.png를 다른 곳에 백업
  2. 새 코드로 폴더 전체 교체
  3. 백업해둔 config.js, logo.png를 다시 덮어쓰기
  4. firebase deploy

8.1 자주 발생하는 문제 (트러블슈팅)

증상원인 / 해결
배포 후 사이트에 접속해도 양산여중 화면이 나옴 ① 브라우저 캐시 → Ctrl+Shift+R 강제 새로고침
② config.js가 제대로 수정되지 않음 → 다시 확인 후 재배포
"Firebase: Error (auth/...)" 메시지 config.js의 firebase 키 값이 잘못됨. Firebase 콘솔 → 프로젝트 설정에서 다시 복사
급식 정보가 표시되지 않음 NEIS 학교코드가 틀림. 1.3절 참고하여 정확한 코드 확인
"Missing or insufficient permissions" Firestore 보안 규칙이 배포되지 않음. firebase deploy --only firestore:rules 실행
관리자 로그인이 안 됨 ① Authentication → Google 활성화 안 됨 (2.4절)
② Gmail이 adminEmails에 없음 (3.2절)

또는 페이지 새로고침 후 1~2분 대기
한 학급만 화면이 안 나옴 URL의 grade/class 숫자가 gradeClasses 범위 밖
(예: 1학년 10반 URL인데 config는 9반까지만)
변경 사항이 전자칠판에 반영 안 됨 전자칠판 Chrome 새로고침 (F5). 그래도 안 되면 IFP 재부팅
