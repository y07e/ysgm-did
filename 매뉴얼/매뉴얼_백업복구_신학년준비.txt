═══════════════════════════════════════════════════════════════
  Part 1. 백업·복구 구조 이해
═══════════════════════════════════════════════════════════════

이 시스템은 "코드"와 "데이터"가 서로 다른 곳에 저장됩니다.
각각의 백업 방식이 다르므로 둘 다 챙겨야 합니다.

┌─────────────────┬───────────────────────┬─────────────┬─────────────┐
│ 종류            │ 저장 위치             │ 자동 백업?  │ 복구 가능?  │
├─────────────────┼───────────────────────┼─────────────┼─────────────┤
│ 코드            │ GitHub +              │ ✅          │ ✅          │
│ (HTML/JS/규칙)  │ Firebase Hosting      │ (git push시)│             │
├─────────────────┼───────────────────────┼─────────────┼─────────────┤
│ 데이터          │ Firebase Firestore    │ ❌          │ ⚠️ JSON     │
│ (공지/시간표 등)│                       │             │ 백업 필요   │
├─────────────────┼───────────────────────┼─────────────┼─────────────┤
│ 로그인 계정     │ Google OAuth          │ ✅          │ ✅          │
│ (관리자 Gmail)  │                       │ (Google관리)│             │
├─────────────────┼───────────────────────┼─────────────┼─────────────┤
│ Firebase 프로젝트│ Firebase 클라우드    │ —           │ ⚠️ 삭제 시  │
│ 자체            │                       │             │ 영구 소실   │
└─────────────────┴───────────────────────┴─────────────┴─────────────┘


▶ 시나리오별 복구 가능성

  A. 본인 PC 망가짐 / 분실
     → 걱정 X. 새 PC에서 GitHub clone + Firebase 로그인이면 끝

  B. 코드 망가짐 (실수로 파일 삭제 등)
     → 걱정 X. GitHub에서 다시 받음

  C. Firestore 데이터 일부 손상 (실수로 삭제)
     → JSON 백업이 있어야 복구 가능
     → 백업 없으면 개별 데이터 영구 소실

  D. Firebase 프로젝트 통째로 삭제
     → 코드: GitHub로 5분 만에 복구
     → 데이터: JSON 백업 있으면 복원 / 없으면 처음부터

  E. 본인이 학교를 떠나거나 사고 발생
     → Firebase 콘솔 접근 권한이 본인 Gmail에만 있으면 큰 문제
     → Part 4 참고하여 사전에 공동 관리자 등록 필수


═══════════════════════════════════════════════════════════════
  Part 2. 데이터 백업 (관리자 작업)
═══════════════════════════════════════════════════════════════

【 백업 시점 】

  ✅ 학기말 (7월, 12월)
  ✅ 학년말 (2월)
  ✅ 큰 변경 작업 전 (시간표 일괄 재입력, 학년 구조 변경 등)
  💡 월 1회 정기 백업 권장


【 백업 절차 】

  1) 관리자 페이지(https://ysgm-did.web.app/admin/) 접속
  2) ⚙️ 설정 → 💾 백업·복원 메뉴
  3) 📥 JSON 백업 다운로드 버튼 클릭
  4) 다운로드된 파일을 보관
     · 파일명 예: backup-ysgm-did-2026-05-20.json

  📂 백업 파일 보관 권장 위치 (2곳 이상)
     · 본인 PC + 클라우드(구글 드라이브, 네이버 클라우드 등)
     · USB 메모리에도 보관하면 더 안전


【 복원 절차 】

  ⚠️ 복원은 매우 신중하게! 현재 데이터를 덮어씁니다.

  1) 관리자 페이지 → ⚙️ 설정 → 💾 백업·복원
  2) 📤 JSON 파일 업로드 버튼
  3) 백업 파일 선택
  4) 미리보기 확인 → 복원 실행

  💡 복원 전에 현재 상태도 한 번 백업해두는 것이 안전


═══════════════════════════════════════════════════════════════
  Part 3. 코드 백업 (GitHub) 및 복구
═══════════════════════════════════════════════════════════════

【 코드 저장소 】

  GitHub URL: https://github.com/y07e/ysgm-did
  소유자 계정: y07eda@gmail.com (양산여중 시스템 담당)


【 자동 백업 】

  코드 수정 후 다음 명령으로 GitHub에 푸시되면 자동 백업:

    git add <변경된 파일>
    git commit -m "변경 내용 설명"
    git push origin main

  💡 본인이 시스템 수정을 직접 하지 않는다면 별도 작업 불필요
  💡 외부 개발자(예: AI 어시스턴트, 위탁 개발자)에게 작업 의뢰 시
     → 작업 후 반드시 git push 까지 진행되었는지 확인


【 코드 복구 (전체 재구축) 】

  본인 PC가 망가지거나 코드 폴더가 사라진 경우:

  1) 새 PC에 Node.js 설치 (https://nodejs.org → LTS)

  2) Firebase CLI 설치
     명령 프롬프트(터미널)에서:
     npm install -g firebase-tools

  3) Firebase 로그인
     firebase login
     → 브라우저에서 학교 대표 Gmail로 로그인

  4) GitHub에서 코드 복제
     git clone https://github.com/y07e/ysgm-did.git
     cd ysgm-did

  5) 재배포
     firebase deploy

  → 5분 이내에 사이트가 그대로 복구됨


【 git 없이 다운로드 (개발 안 해도 OK) 】

  1) 브라우저로 https://github.com/y07e/ysgm-did 접속
  2) 녹색 "Code" 버튼 → "Download ZIP"
  3) 압축 해제 → 위 4번부터 진행


═══════════════════════════════════════════════════════════════
  Part 4. Firebase 프로젝트 멤버 관리
═══════════════════════════════════════════════════════════════

⚠️ 매우 중요: 본인 부재 시를 대비한 공동 관리자 등록

이 시스템의 Firebase 콘솔(데이터·설정 관리 권한)이 본인 Gmail
하나에만 등록되어 있으면, 본인이 학교를 떠나거나 사고가 났을 때
시스템 전체 통제권이 사라집니다.

→ 최소 1명, 권장 2명을 Firebase 프로젝트 공동 멤버로 등록하세요.


【 공동 관리자 등록 절차 】

  1) Firebase 콘솔 접속
     https://console.firebase.google.com
     → ysgm-did 프로젝트 선택

  2) 좌측 메뉴 ⚙️ (톱니바퀴) → 사용자 및 권한

  3) "구성원 추가" 버튼

  4) 추가할 사람의 Gmail 입력

  5) 역할 선택:
     · 소유자 (Owner)  — 모든 권한 + 다른 멤버 관리
     · 편집자 (Editor) — 모든 권한 (다른 멤버 추가/삭제 제외)

     ⚠️ 후임 시스템 담당자라면 "소유자" 권장
     ⚠️ 학교장·교감 등 백업용이라면 "편집자"도 충분

  6) 추가 → 해당인에게 초대 메일 발송됨


【 권장 멤버 구성 】

  · 본인 (시스템 담당)              — 소유자
  · 교감 또는 교무부장              — 소유자 (백업)
  · 행정원 1명                      — 편집자 (운영 지원)


【 GitHub 저장소 공동 관리 】

  Firebase와 별도로 GitHub 저장소 권한도 양도 가능:

  1) https://github.com/y07e/ysgm-did
  2) Settings → Collaborators → Add people
  3) 후임자 GitHub 계정 입력 → 권한 선택 (Write 권장)

  → 후임자가 본인 GitHub 계정으로 코드 수정 가능


═══════════════════════════════════════════════════════════════
  Part 5. 신학년도 초기화 작업
═══════════════════════════════════════════════════════════════

매년 2월 말 ~ 3월 초 신학년 시작 전에 진행하는 작업입니다.
업로드·설정 기반이라 행정원·교무 담당이 직접 처리할 수 있으며,
한 번 익숙해지면 30분~1시간 이내에 모든 셋업 가능합니다.

★ 핵심: 코드 수정이나 재배포는 전혀 필요 없습니다.
  모두 관리자 페이지(https://ysgm-did.web.app/admin/)에서 처리합니다.


【 5-1. 사전 준비물 (신학년 시작 2주 전) 】

  ✅ 현재(작년) 데이터 JSON 백업 1회 (보존용)
       → ⚙️ 설정 → 💾 백업·복원 → 백업 파일 다운로드
       → 안전한 곳(드라이브 등)에 보관

  ✅ 신학년 담임 명단
       → 방법A: 학교 "담임·비담임·부서표" PDF (그대로 사용 가능)
       → 방법B: 시스템 엑셀 양식에 학년·반·이름 입력
       ※ PIN은 비워도 됨 (자동으로 해당 연도, 예: 2027)

  ✅ 신학년 NEIS 시간표 엑셀 (3개 학년 각 1파일)
       → NEIS 접속 → 학년별 시간표 → 엑셀 저장

  ✅ 변동된 관리자 명단 (있을 때만)
       → 새 교무부장·교감 등 Gmail / 그만두는 관리자 명단

  ✅ 학년별 학급 수 (작년과 다를 때만 확인)


【 5-2. 신학년 초기화 — 순서대로 】

  ───────────────────────────────────────────────
  ① 학급 수 설정 (작년과 다를 때만)
  ───────────────────────────────────────────────
  ─ ⚙️ 설정 → 🏫 학교 설정
  ─ 1·2·3학년 학급 수 입력 → 💾 학교 설정 일괄 저장
  ─ 저장 즉시 학급 목록·시간표·교실 URL 전체 자동 반영
  ★ 예전과 달리 코드 수정 불필요 — 이 화면에서 저장만 하면 끝

  ───────────────────────────────────────────────
  ② 담임 일괄 등록 (PDF 또는 엑셀)
  ───────────────────────────────────────────────
  ─ ⚙️ 설정 → 👥 교사 관리 → "📋 담임 일괄 등록" 카드

  [방법 A] 학교 부서표 PDF 그대로 올리기 (가장 빠름)
     ─ 파일 선택 → 담임·비담임·부서표 PDF 업로드
     ─ 상단 "학급 담임" 표가 자동 인식됨
     ─ 미리보기에서 학년-반-이름 확인
     ─ "기존 담임 전체 삭제 후 등록" 체크 (신학년 권장)
     ─ "✅ N명 일괄 등록" 클릭

  [방법 B] 엑셀 양식 이용
     ─ "📥 엑셀 양식 다운로드" → 학년·반 미리 채워진 양식
     ─ 이름만 입력 후 업로드 → 미리보기 → 등록

  ※ PIN을 비우면 해당 연도(예: 2027)로 자동 설정됩니다.
    담임은 첫 로그인 후 본인 PIN으로 변경 권장.
  ※ 미리보기에서 이름이 이상하면 PDF 대신 엑셀 양식 사용.

  ───────────────────────────────────────────────
  ③ 관리자 변경 (있을 때만)
  ───────────────────────────────────────────────
  ─ ⚙️ 설정 → 👥 교사 관리 → 교사 등록 (역할: 관리자)
  ─ 떠나는 관리자는 삭제, 새 관리자는 Gmail로 등록
  ─ 새 관리자가 본인 Gmail로 첫 로그인 시 자동 활성화

  ───────────────────────────────────────────────
  ④ 기초 시간표 엑셀 일괄 업로드
  ───────────────────────────────────────────────
  ─ 📅 일정 관리 → 기초 시간표 편집 → 📤 나이스 엑셀 업로드
  ─ 1학년 → 2학년 → 3학년 파일 순서로 (각 미리보기 후 적용)
  ─ 약 5분 소요

  ───────────────────────────────────────────────
  ⑤ 급식 운영 기간 (3월) 설정
  ───────────────────────────────────────────────
  ─ 🍱 급식 시간 → "새 운영 기간 추가"
  ─ 시작/종료일, 학급별 시작 시각, 회전 주기 입력
  ─ 이후 매월 "📋 다음 달 복제"로 빠르게 추가

  ───────────────────────────────────────────────
  ⑥ 학사일정 · D-Day 입력
  ───────────────────────────────────────────────
  ─ 📅 일정 관리 → 📆 학사일정: 3~7월 주요 일정 (한 주 2건 권장)
  ─ 📅 일정 관리 → 🎯 D-Day: 시험·행사 (동시 활성 2개 권장)
  ─ TIP: 학사일정 항목의 "🎯 D-Day 설정" 버튼으로 바로 등록 가능

  ───────────────────────────────────────────────
  ⑦ 작년 공지사항 정리
  ───────────────────────────────────────────────
  ─ 📢 공지사항 등록 → 작년 만료 공지 삭제 또는 비활성화


【 5-3. 신학기 시작 후 확인 】

  ✅ 전자칠판 몇 대 새로고침 → 신학기 화면 정상 표시 확인
  ✅ 1학년 1반 / 3학년 마지막 반 등 양 끝 학급 샘플 점검
  ✅ 결보강(일일 시간표 변경): 컴시간 결보강 PDF 업로드로 매일 반영
       → 📅 일정 관리 → 일일 시간표 변경 → "📄 결보강 PDF 업로드"
  ✅ 신년 담임에게 안내 페이지 공유
       → https://ysgm-did.web.app/teachers/ (로그인 방법·화면 설명 포함)
  ✅ 신년 관리자에게 관리자 매뉴얼 배포


【 5-4. 사라지지 않는 것들 (그대로 유지됨) 】

  · 학교명, 로고, NEIS 학교 코드, 학급 수(작년 값)
  · 수업 시간 설정 (기초 시간), 단축 수업 설정
  · 기존 관리자 계정
  · Firebase 프로젝트, 도메인(ysgm-did.web.app)
  · 전자칠판 설치 앱 (재설치 불필요 — 자동으로 최신 화면)
  · GitHub 저장소

  → 신학기 작업은 사실상 "담임 명단 + 시간표 + 학사일정/급식"
     입력만 하면 끝납니다. (학급 수 변동 시 ①만 추가)

  Part 6. 트러블슈팅 / FAQ
═══════════════════════════════════════════════════════════════

Q. JSON 백업 파일이 너무 커요. 정상인가요?
A. 1년치 데이터면 보통 1~5 MB 정도가 정상. 50 MB 넘으면
   불필요한 누적 데이터(과거 공지 등) 정리 권장.

Q. 백업 파일을 메일로 보내도 되나요?
A. 가능하지만 민감 정보(담임 이메일, PIN 해시) 포함되므로
   학교 내부 또는 본인 메일로만. 외부 공유 금지.

Q. 신학년 초기화 중 실수해서 작년 데이터로 돌리고 싶어요.
A. 사전 작업에서 받아둔 JSON 백업으로 복원하면 됩니다.
   ⚙️ 설정 → 💾 백업·복원 → 업로드.

Q. 후임자가 시스템을 인계받으려면 무엇이 필요한가요?
A. 다음 3가지를 양도:
   1) Firebase 프로젝트 소유자 권한 (Part 4 참고)
   2) GitHub 저장소 권한 (Part 4 참고)
   3) 본 매뉴얼 + 관리자 매뉴얼 + 담임 매뉴얼 + 배포 가이드
   ⚠️ Firebase 콘솔 로그인 계정(y07eda@gmail.com)은 양도하지 말 것
   → 본인 개인 Gmail이므로 후임자는 본인 Gmail을 새 소유자로 등록받음

Q. 학년별 학급 수가 바뀌면 (예: 1학년이 9반 → 10반)?
A. ⚙️ 설정 → 🏫 학교 설정에서 학급 수 입력 후 저장하면 끝.
   코드 수정·재배포 불필요. 학급 목록·시간표·교실 URL이 즉시 반영됩니다.
   (학급 수를 줄여도 기존 데이터는 삭제되지 않고 숨겨질 뿐이라 안전)

Q. 담임 일괄 등록 시 PDF가 인식이 안 돼요.
A. 학교 부서표 양식이 바뀌면 자동 인식이 어긋날 수 있습니다.
   → 미리보기에서 이름이 이상하면 "엑셀 양식 다운로드"로 대체하세요.
   → 또는 시스템 담당자에게 새 PDF를 전달해 좌표 조정 요청.

Q. 담임 PIN을 따로 안 정했는데 괜찮나요?
A. 비우면 해당 연도(예: 2027)로 자동 설정됩니다.
   담임이 첫 로그인 후 본인 PIN으로 변경하도록 안내하면 됩니다.

Q. 학교가 통폐합되는 등 큰 구조 변경이 있으면?
A. 학급 수 변경은 위(학교 설정)에서 가능하지만,
   학년 수 자체가 바뀌는 등 큰 변경은 시스템 담당자 문의.

Q. Firebase 프로젝트를 실수로 삭제했어요!
A. 삭제 후 30일 이내라면 Firebase 콘솔에서 복구 신청 가능.
   30일 지나면 영구 소실 → 새 프로젝트 생성 + 코드 재배포 +
   JSON 백업 복원으로 새로 시작 (도메인이 바뀜).

Q. 새 학교에 이 시스템을 적용하고 싶어요.
A. "배포가이드_양산제일고.pdf" 파일 참고. 학교당 약 2~4시간
   작업으로 독립 운영 가능.
